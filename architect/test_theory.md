# 测试理论

## 静态测试
需求、设计、结构分析、流程图分析

2021下考题：是指被测试程序不在机器上运行，而采用人工监测和计算机辅助分析的手段对程序进行监测

## 黑盒测试（2021下考题：也称为功能测试）
依据 SRS 软件需求规格说明 Software Requirements Specification
- 边界值分析
- 因果图
- 判定表/判定树：多个逻辑条件取值组合所构成的负载情况下，分别要执行哪些不同的动作（2022下考题）
- 等价类划分法：有效/无效 （符合/不符合《需求规格说明书》）
- 正交实验法

## 白盒测试
- 逻辑覆盖
- 语句覆盖
- 判定覆盖 分支覆盖
- 条件覆盖
- 判定/条件覆盖
- 条件组合覆盖
- 路径覆盖 （2022下考题：测试强度最高的）
- 循环覆盖
- 基本路径测试

## 灰盒测试（输入输出与逻辑）

## 测试阶段
- 单元测试
- 集成测试
- 回归测试：软件原有的、正确的功能、性能和其他规定的要求的不损害性（2022下考题）
- 冒烟测试
- 系统测试：功能、性能、健壮性、安装或反安装、用户界面、压力、可靠性及安全性
  - （2024下考题：系统测试是为了发现需求分析出现的错误）
- 验收测试：针对SRS，在交付前以用户为主进行的测试。
- Alpha 测试：用户 在 开发环境
- Beta  测试：用户 在 实际使用环境

### Web 服务器测试
- 基准性能测试
- 压力测试
- 可靠性测试 （2021下考题）

性能指标：（2021下考题：不包括链接正确跳转）
- 连接速度
- 最大并发连接数
- 响应延迟
- 吞吐量


### 自动化测试
- 线性脚本：是录制手工测试的测试用例时得到的脚本
- 结构化脚本：具有各种逻辑结构和函数调用功能
- 共享脚本：是指一个脚本可以被多个测试用例使用
- 数据驱动脚本：是指将测试输入存储在独立的数据文件中，而不是脚本中
- 关键宇驱动脚本：是数据驱动脚本的逻辑扩展，用测试文件描述测试用例


# 缺陷管理
2020下论文2：

IEEE 标准 软件测试中所发现的缺陷主要包括：
1. 输入/输出
2. 逻辑
3. 计算
4. 接口
5. 数据

从软件测试角度还可以将缺陷分为五类：
1. 功能
2. 系统
3. 加工
4. 数据
5. 代码

Beizer将缺陷分为十级：
1. 轻微
2. 中等
3. 使人不悦
4. 影响使用
5. 严重
6. 非常严重
7. 极为严重
8. 无法容忍
9. 灾难性
10. 传染性
