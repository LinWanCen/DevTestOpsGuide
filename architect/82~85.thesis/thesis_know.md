## 2018年

1. 论软件开发过程RUP及其应用（最简单）
   - RUP 的四个阶段：
     1. 初始阶段，定义最终产品视图和业务模型，并确定系统范围；
     2. 细化阶段，设计及确定系统的体系结构，制订工作计划及资源要求：
     3. 构造阶段，构造产品并继续演进需求、体系结构、计划直至产品提交：
     4. 移交阶段，把产品提交给用户使用。
   - RUP 的基本特征：
     - 受控的迭代式增量开发
     - 用例驱动
     - 以软件体系结构为中心
2. 论软件体系结构的演化（难）
   - 系统演化的六个步骤：
     1. 需求变化归类
     2. 制订体系结构演化计划
     3. 修改、增加或删除构件
     4. 更新构件的互相作用
     5. 构件组装与测试
     6. 技术评审
3. 论面向服务架构设计及其应用（中等）
   - 主要技术和标准：
     1. UDDI （统一描述、发现和集成协议）
     2. WSDL (Web 服务描述语言）
     3. SOAP （简单对象访问协议）
     4. BPEL （业务流程执行语言）
   - 构建SOA架构时遇到了哪些问题？如何解决？
     1. SOA 系统如何与原有系统中的功能进行集成。
     2. SOA 系统服务的设计以及服务粒度的控制。
     3. 无状态服务的设计以及服务流程的组织。
4. 论NoSQL数据库技术及其应用（简单）
   - 常见的 NoSQL 数据库技术
     1. 键值存储数据库：Tokyo Cabinet/Tyrant、 Redis、 Voldemort、 Oracle BDB
     2. 列存储数据库：Cassandra、HBase、Riak
     3. 文档型数据库：CouchDB、MongoDb、SequoiaDB
     4. 图数据库：Neo4J、InfoGrid、Infinite Graph
   - NoSQL数据库的主要适用场景
     - 数据模型比较简单。
     - 需要灵活性更强的IT系统。
     - 对数据库性能要求较高。
     - 不需要高度的数据一致性。 
     - 对于给定key，比较容易映射复杂值的环境。

3. 论软件系统架构评估及其应用（难）
   - SAAM (Scenarios-based Architecture Analysis Method）（场景驱动的架构分析方法）
     - 评估目标：对描述应用程序属性的文档，验证基本体系结构假设和原则
     - 质量属性：可修改性、可移植性、可扩充性等
     - 评估活动：1.场景开发、2.体系结构描述、3.单个场景评估、4.场景交互和总体评估
   - ATAM (Architecture Tradeoff Analysis Method)（架构权衡分析方法）
     - 评估目标：提供一种理解软件体系结构的能力的方法，在多个质量属性之间折中的必要性。
     - 质量属性：性能、实用性、安全性和可修改性
     - 评估活动：1.场景和需求收集、2.体系结构视图和场景实现、3.属性模型构造和分析、4.折中。
4. 论数据湖技术及其应用（最难）

| 特性 | 数据湖 | 数据仓库 |
|------|--------|----------|
| 主要数据来源 | 来自物联网设备、互联网、移动应用程序、社交媒体和企业应用程序的结构化、半结构化和非结构化数据 | 来自事务系统、运营数据库和业务线应用程序的结构化数据 |
| 数据模式转换时机 | 数据进入数据湖时不进行模式转换，在进行实际数据分析时才进行模式转换 | 在进入数据仓库之前（需要提前设计数据仓库的Schema） |
| 数据存储成本 | 通常基于非关系型数据库，数据存储成本相对较低 | 通常基于关系型数据库，数据存储成本高 |
| 数据质量 | 原始的、未经处理的数据 | 可作为重要事实依据的高质量数据 |
| 面对用户 | 业务分析师、应用开发人员和数据科学家 | 业务分析师 |
| 主要支撑应用 | 机器学习、预测分析、数据发现和分析 | 批处理报告、商务智能（BI）和数据可视化 |

## 🏆 整体推荐（最简单）

综合十年真题来看，论文难度因个人项目经历而异，但从普遍可写性、技术门槛最低、模板化最容易的角度，以下三道题**对考生整体而言是最简单的**：

1. **2018年——论软件开发过程RUP及其应用**  
   RUP有固定流程框架（初始、细化、构建、交付四个阶段），知识结构清晰，评卷标准明确，是最容易“套模板”拿分的题目。

2. **2020年——论数据分片技术及其应用**  
   技术原理相对固定（垂直分片、水平分片、混合分片），在电商、支付等高并发场景中实践充分，尤其对有数据库经验的考生来说最易上手。

3. **2024年——论单元测试方法及应用**  
   单元测试几乎是每位开发者的日常技能，技术门槛最低，只要结合具体项目中的单元测试实践即可展开论述，无需高深架构设计经验。
