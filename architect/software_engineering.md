## 软件能力成熟度模型 CMMI
Capability Maturity Model Integration for Software
- Level 1 初始级 过程随意混乱、成本超支
- Level 2 已管理级 确保项目级的过程，建立明确的目标，并能实现成本、进度和质量目标等。
- Level 3 已定义级 有标准流程、制度化、组织过程资产收集。（2021下考题：流程）
- Level 4 量化管理级 定量目标、可预测
- Level 5 优化级 最高级、创新优化、关注绩效。

## 系统分析与设计
- OOA 面向对象的分析 Object Oriented Analysis
  1. 确定对象和类
  2. 确定结构
  3. 确定主题
  4. 确定属性
  5. 确定方法
  - 原则：抽象(过程、数据)、封装、继承、分类、聚合组装、关联、消息通信、粒度控制、行为分析
- 结构化分析 Structured Developing：面向数据流的需求分析方法，功能分解
  - 行为模型 STD 状态转换图 State Transition Diagram
  - 功能模型 DFD 数据流图 Data Flow Diagram
  - 数据模型 ER 实体关系图 Entity-Relationship Diagram
- SD 结构化设计 Structured Design
  - 特征：信息隐蔽与隐藏 模块化 高内聚与低耦合
  - 模块基本属性：功能、逻辑、状态
  - 内聚从低到高：偶然（没有联系）、逻辑、时间、过程、通信（同一数据结构）、顺序（输出是下个的输入）、功能
    （2021下考题：属于高内聚的是功能内聚）
  - 偶合从低到高：无直接耦合、数据（值传递）、标记（引用传递）、控制（控制逻辑信息）、通信（共享输入或输出）、公共（多线程同一缓存或数据库）、内容（不通过方法字节访问成员变量）
    （2021下考题：尽量使用数据耦合、少用控制耦合和特征耦合、限制公共环境耦合的范围、完全不用内容耦合）
  - 结构化概要设计：(2022下考题：顺序图不属于结构化设计工具)
    - SC 系统结构图 Structure Chart 又称为模块结构图
    - PFD 程序流程图 Program Flow Diagram
    - N-S图 盒图
    - HIPO 图 (IBM 1970) Hierarchy plus Input-Process-Output
      - 层次图：从上到下分模块
      - IPO图：每个模块的输入、处理、输出
    - PAD 问题分析图 Problem Analysis Diagram
    - PDL 过程设计语言 Process Design Language 也称为结构化语言或伪代码
    - 判定表
    - 判定树
  - 结构化详细设计：顺序图、通信图=协作图、状态图、活动图、包图、构件图

1. 需求变化归类
2. 制订体系结构演化计划
3. 修改、增加或删除构件
4. 更新构件的相互作用
5. 构件组装与测试
6. 技术评审
